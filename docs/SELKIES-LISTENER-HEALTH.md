# Selkies listener health candidate

The 2026-09-24 OVH GRA11 L4 canary showed gateway `upstream_connect_refused` while the container was running, `pgrep -f selkies-gstreamer` still returned the same PID, and the Unix socket pathname still existed. The process-only health loop did not restart Selkies. The worker's socket-generation repin could not repair a listener that was not accepting on its existing socket.

This local candidate checks the container's `/proc/net/unix` table for the exact live listening socket, without opening an extra WebSocket connection. After the first healthy observation, two consecutive five-second checks that find no listener trigger the existing Selkies/compositor restart path. Initial startup and each restart get a 30-second bind grace period so a live Selkies process is not restarted while it is still opening signaling. An unreadable `/proc/net/unix` observation does not trigger a restart. The helper rejects symlinks, stale socket files, bound-but-not-listening sockets, and relative paths. Its Linux socket tests and `bash -n entrypoint.sh` pass.

The worker candidate from `ForcesPT/dpadplay` revision `718ce09` repins the socket after this supervisor creates a replacement. The pinned OVH host launcher still offers the legacy stream overlay; the session controller strips it only for an exact allowlisted image digest. Any new image release must add its exact digest to that controller gate and its OVH cold-start selector, then verify that the baked entrypoint is the one Docker runs.

The full source Dockerfile currently fails at the pinned Selkies v1.6.2 GitHub release asset (HTTP 404). `Dockerfile.listener-health` derives from the exact prior production image `forcespt/dpadcloud-gaming@sha256:a6588db47431191308fe7a38c1b1c8854da04e0473fef5c203787d5188cdad4f`. The first derivative was published as digest `sha256:78a07169018f50c8e5f16d62e0db3cffafc72102062f91a7d2c1e90a7be66778`. A single paid L4 canary on 2026-09-24 still produced a browser connection error after listener restarts; production API and worker pins were rolled back and the VM was destroyed. See the control-plane rollout note for bounded evidence.

The same canary logged one `GSTWebRTCAppError` in a category consistent with the pinned source's `Failed to transition pipeline to PLAYING` raise. Its exact return value was lost when the session container was removed. In the pinned Selkies 1.6.2 source, `start_pipeline()` rejects every `set_state(PLAYING)` result except `SUCCESS`. A live-source GStreamer pipeline in the same image reproducibly returns `ASYNC`, which is a valid nonfailure result. `scripts/dpad-patch-selkies-gst-state.py` now accepts `SUCCESS`, `ASYNC`, and `NO_PREROLL` while still rejecting `FAILURE` and unknown results. The patch is applied to the derivative and full source Dockerfiles, with an exact-source and idempotence gate. The built local image passed semantic tests against its installed Selkies method for all four state results. Its real Unix signaling server passed authenticated HELLO, SESSION_OK, and offer relay without a GPU.

The new derivative is a **local candidate only**. GPU pipeline startup, browser video/audio, reconnect, and listener lifetime remain unverified. Before any rollout, publish under a fresh tag, verify the immutable registry digest, update both control-plane gates to that exact digest, and repeat a single authorized paid L4 canary with the GStreamer return value and bus diagnostics captured before teardown.
