# DpadCloud Gaming Containers — GPU Image Repo

Hermes: this is the GPU container image repo for DpadPlay. The control plane (web + orchestrator) lives in the companion repo at `../dpadplay`. Always read the docs below at session start before working.

## Read these docs at session start (in this order)

1. `docs/PROJECT_STATE.md` — the image state, latest session notes, baked-in fixes, known limitations. THIS IS THE RESUME POINT.
2. `docs/IMAGE-RUNBOOK.md` — the launch recipe, env-var reference, troubleshooting.
3. `docs/STORES-PLAN.md` — the multi-store plan (Steam, Epic, GOG, Battle.net), the Lutris/picker decision, the umu pivot.
4. `docs/WAYLAND-ARCHITECTURE.md` — the gst-wayland-display compositor pivot decision (retires gamescope-headless for multi-store).

## What this repo builds

One multi-stage Dockerfile, two final images:

| Tag | Target | Use |
|-----|--------|-----|
| `:dpad-SteamOS` | `vast-vm` | Steam + gamescope + Selkies (full VM, userns) |
| `:dpad-SteamOS-rtx50` | `vast-vm` + CUDA 12.8.1 | RTX 50 / Blackwell variant |
| `:dpad-heroic` | `vast-docker` | Heroic desktop + Selkies (deprecated for v2) |

Base: Ubuntu 24.04 + CUDA 12.5.1, Selkies-GStreamer 1.24.6 (WebRTC + NVENC), coturn, cloudflared, Xorg/Xvfb, Mesa, Vulkan, PulseAudio.

## Build & push

```bash
cd container-gaming

# Standard (Ada/Turing/Ampere)
docker build --target vast-vm -t forcespt/dpadcloud-gaming:dpad-SteamOS .
docker push   forcespt/dpadcloud-gaming:dpad-SteamOS

# RTX 50 / Blackwell
docker build --target vast-vm --build-arg CUDA_VERSION=12.8.1 --build-arg CUDA_PKG=12-8 \
  -t forcespt/dpadcloud-gaming:dpad-SteamOS-rtx50 .
docker push   forcespt/dpadcloud-gaming:dpad-SteamOS-rtx50
```

## The compositor path (production default)

`DPAD_COMPOSITOR=wayland-display` + `DPAD_WAYLAND_CLIENT=sway` + `DPAD_STORE_SHELL=picker`
- gst-wayland-display (Smithay micro-compositor) captures + composites
- sway provides XWayland for Electron/X11 apps
- dpad-launcher picker is the session shell (store launcher, not Lutris)
- gamescope is demoted to an XWayland-providing client (not the compositor)

## Critical baked-in fixes (don't re-discover)

- **gamescope drmProps headless patch** — gamescope returns zeros on VkPhysicalDeviceDrmPropertiesEXT, patch relaxes the abort
- **NVENC #1249 interposer** — filters GET_ATTACHED_IDS to mounted GPUs (driver 570-609, multi-GPU)
- **Gamepad 6-layer chain** — interposer + SDL_JOYSTICK_LINUX_CLASSIC + mknod + UDEV_DISABLE + JSIOCGNAME + i386/x86_64 .so
- **Targeted chown** (not `chown -R`) — blanket chown wastes 119s on overlayfs; use `find ! -user dpad -exec chown`
- **Steam install root ON the volume** — symlink ~/.steam/debian-installation -> <vol>/steam-install
- **Volume mount by label/exclusion** — virtio letter mapping is unreliable after detach
- **entrypoint bind-mount hotfix** — dpad-launch-session bind-mounts host entrypoint over baked one (no image rebuild needed)
- **unattended-upgrades disabled** — apt-daily timer killed containers mid-session (exit 137)
- **Mouse scroll inversion** — v1.6.2 constants are inverted; button 5 = scroll UP, button 4 = scroll DOWN (don't swap back)

## Driver matrix (don't get this wrong)

| Driver build | Works? | Action |
|--------------|--------|--------|
| Desktop proprietary 580 (OVH) | YES (both compositors) | Keep, no swap |
| Server 580-server (Scaleway) | NO (black screen) | Swap to open 580 |
| 595 (UpCloud) | NO (crashes EGL) | Downgrade to open 580 |
| R570-open (Hyperstack) | YES | Keep |
| R580-open (MassedCompute) | YES | Keep |

## Gotchas

- `ensure_driver_580` is Scaleway-gated — don't make it non-gated (would break OVH).
- The 595 -> 580 downgrade on UpCloud is MANDATORY (not avoidable).
- SSH key must be registered in Scaleway IAM (not just cloud-init) — scw-fetch-ssh-keys wipes authorized_keys on every boot.
- WebRTC needs HTTPS (secure context) — direct http:// IP won't establish RTCPeerConnection.
- Vast Docker images (:dpad-heroic) are deprecated — v2 uses :dpad-SteamOS exclusively.
- The Battle.net CEF needs `--disable-gpu --in-process-gpu` under Xwayland-in-SLR.
- umu -> pressure-vessel -> bwrap needs `--cap-add SYS_ADMIN` + `seccomp`/`apparmor`/`systempaths` unconfined.
